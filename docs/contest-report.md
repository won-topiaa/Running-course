## 1. 서비스 개요

### 1.1 문제 정의

러닝은 진입 장벽이 가장 낮은 운동이지만, 자신의 체력 수준에 맞는 코스를 찾는 것은 여전히 어렵다. 기존 러닝 앱들은 GPS 기록과 소셜 기능에 집중하며, **"내 체력에 맞는 코스가 어디인가"**라는 핵심 질문에 답하지 못한다.

구체적으로 세 가지 문제가 존재한다:

| 문제 | 현상 | 원인 |
|------|------|------|
| **체력 수준 파악 불가** | 러너 대부분이 자신의 객관적 체력 수준을 모름 | 체력 측정 데이터가 개인에게 환원되지 않음 |
| **코스 미스매치** | 초보자가 급경사 코스에서 포기, 상급자가 단조로운 코스에서 지루함 | 코스 추천이 거리 기준 단일 축에 의존 |
| **정보 분절** | 경로, 체육시설, 혼잡도 정보가 서로 다른 서비스에 흩어져 있음 | 공공데이터가 서비스에 통합되지 않음 |

### 1.2 해결 방안

**런코스**는 국민체력100 측정결과 데이터(약 295만 건)에서 추출한 연령·성별 체력 분포를 기반으로, 사용자의 체력을 **101개 분위 위에 위치**시키고, 그에 맞는 **거리·경사·경로 스타일을 연속적으로 처방**하여 개인 맞춤 러닝 코스를 생성한다.

단순한 "체력 좋으면 먼 거리" 식 3단계 분류가 아니라, **분위 기반 연속 보간**으로 사용자 체력에 비례하는 매끄러운 처방을 제공한다.

## 2. 데이터 활용 상세

### 2.1 국민체력100 체력측정결과 (데이터셋 15108938)

#### 역할: 서비스의 핵심 — 개인 체력 백분위 산출 및 코스 처방

**수집 방법**

| 항목 | 내용 |
|------|------|
| API 엔드포인트 | `apis.data.go.kr/B551014/SRVC_NFA_TEST_RESULT/TODZ_NFA_TEST_RESULT_NEW` |
| 전체 레코드 수 | 2,950,737건 |
| 수집 표본 | 48,000건 (12개 코호트 × 4,000건) |
| 코호트 | 남/여 × 20대/30대/40대/50대/60대/70+ |
| 측정 항목 | VO₂max, 악력, BMI, 유연성, 제자리멀리뛰기, 10m 왕복, 반응시간 |
| 수집 스크립트 | `scripts/fetch-fitness-norm.mjs` |

**샘플링 전략**

페이지 순차 수집 시 특정 연도(2023 Q1)에 편향되는 문제를 발견하여, **연도별 균등 슬라이스 샘플링**을 적용하였다. 2022 Q1~Q4, 2023 Q1~Q4, 2024 Q1~Q2에 걸쳐 코호트별 17~26개월 시간 범위의 표본을 확보하였다.

**데이터 정제**

| 정제 항목 | 방법 | 검증 |
|---------|------|------|
| VO₂max 측정방식 분리 | 스텝+트레드밀만 채택, 왕복 달리기 제외 | 왕복 달리기 중앙값이 2~3 낮음 (6개 코호트 교차 검증) |
| 악력 집계 | max(좌, 우) 사용 | 상대악력 역산으로 1000/1000건 일치 확인 |
| 미측정값 분리 | 0값 72,015건을 미측정으로 분류 | 실제 이상치 154건과 분리 |
| BMI 검증 | 체중/(신장m)² 역산 | 2999/3000건 일치 (1건은 반올림 차이) |
| 분위 압축 | 코호트당 4,000건 → 101개 분위 | 0, 1, 2, ..., 100 분위 연속 보간 정밀도 확보 |

**활용 흐름**

```
원시 데이터 (295만 건)
    ↓ 샘플링 (코호트별 4,000건)
    ↓ 정제 (측정방식 분리, 미측정값 제거)
    ↓ 분위 압축 (101개 분위)
fitnessNorm.json (12코호트 × 7항목 × 101분위)
    ↓ kspoFitness.ts (백분위 산출)
    ↓ fitness.ts (연속 보간 처방)
    ↓ courseBuilder.ts (코스 생성)
사용자에게 맞춤 코스 제시
```

사용자가 연령, 성별, 체력 측정값(VO₂max 등)을 입력하면:
1. 해당 코호트의 분위 분포에서 **백분위**를 산출한다
2. 백분위에 따라 **거리(km), 최대 경사(%), 인터벌 비율(%)**을 연속 보간한다
3. 처방값을 기준으로 코스를 생성하고, 다축 점수화로 최적 경로를 선정한다

### 2.2 공공체육시설 현황 (데이터셋 15107764)

#### 역할: 러닝 코스 주변 편의시설 안내

**수집 방법**

| 항목 | 내용 |
|------|------|
| API 엔드포인트 | `apis.data.go.kr/B551014/SRVC_SFMS_FACIL_INFO/TODZ_SFMS_FACIL_INFO` |
| 전체 레코드 수 | 44,681건 |
| 서울 필터링 후 | 약 3,000건 (좌표 유효 시설) |
| 수집 스크립트 | `scripts/fetch-facilities.mjs` |

**활용 방식**

코스를 생성하거나 추천 코스를 열면, **경로를 따라 500m 이내의 공공체육시설**을 자동으로 검색하여 안내한다.

검색 알고리즘:
- 경로를 20등분하여 각 지점에서 반경 검색 수행
- **출발점과 도착점**에서는 1.5배 확대 반경으로 검색 (러너가 시설을 이용할 가능성이 높은 구간)
- 중복 제거 후 거리순으로 최대 4개 시설 표시
- 시설 편의정보 표시: 화장실, 주차장, 샤워실, 보관함, 트랙

**표시 화면**: 코스 생성(BuildScreen), 추천 코스 상세(CourseDetailSheet), 경로 시트(RouteSheet)

### 2.3 체력측정 건수 (데이터셋 15114286)

#### 역할: 국민체력100 참여 현황 시각화 — 서비스 수요 근거

**수집 방법**

| 항목 | 내용 |
|------|------|
| API 엔드포인트 | `apis.data.go.kr/B551014/SRVC_TODZ_NFA_TEST_CENTER_CNT/TODZ_NFA_TEST_CENTER_CNT` |
| 수집 스크립트 | `scripts/fetch-test-counts.mjs` |
| 집계 단위 | 연도별 측정건수, 연령대별 참여율, 서울 구별 인증센터 |

**활용 방식**

추천 코스 탭 하단에 **국민체력100 참여 현황 인사이트** 카드를 배치하여, 사용자에게 국민체력100 제도의 규모와 성장을 시각적으로 전달한다.

시각화 구성:
- **핵심 지표 3개**: 연간 측정건수(523,800건), 전국 인증센터 수(162개소), 서울 센터 수(25개소)
- **연도별 측정 추세**: 최근 6개년 미니 바 차트 (2015~2024 10개년 데이터 중 최근 6년 표시)
- **연령대별 참여 비율**: 7개 연령대(10대~70대 이상) 수평 바 차트
- **서울 현황**: 25개 구 인증센터의 연간 측정건수 합계

이 시각화는 "국민체력100이 이렇게 큰 제도"라는 인식을 심어주고, 체력 평가 기능 사용을 유도하는 역할을 한다.

## 3. 핵심 기능

### 3.1 체력 평가 시스템

국민체력100 데이터를 기반으로 사용자의 객관적 체력 수준을 평가한다.

**입력**: 연령, 성별, VO₂max(또는 Cooper 12분 검사 거리), 악력, BMI 등
**출력**: 동일 연령·성별 대비 백분위 + 코스 처방(거리, 경사, 인터벌)

핵심 알고리즘:
- **VO₂max 추정**: Daniels & Gilbert VDOT 공식 (일반 러닝) + Cooper 공식 `(거리m - 504.9) / 44.73` (12분 검사)
- **백분위 산출**: 12개 코호트별 101개 분위 테이블에서 선형 보간
- **연속 처방**: 앵커 포인트 기반 보간으로 백분위에 비례하는 매끄러운 처방값 산출
  - 0.2km 이하 점프 보장 (급격한 처방 변화 방지)
  - VO₂max 항목 필수 (악력만으로 처방하지 않음)

> **[스크린샷 A: 체력 평가 입력 화면]**

### 3.2 Cooper 12분 검사

앱 내에서 직접 Cooper 12분 달리기 검사를 수행하고, 결과에서 VO₂max를 추정하여 체력 평가에 반영한다.

- GPS 첫 수신 시 타이머 자동 시작 (벽시계 기준)
- 일시정지 불가 (검사 프로토콜 준수)
- 음성 큐: 10분 / 5분 / 3분 / 1분 / 10초 남음 안내
- 완료 시: VO₂max 추정값, 동 연령대 백분위, 간극 경고(GPS 정확도 부족 시) 표시

> **[스크린샷 B: Cooper 12분 검사 실행 화면]**

### 3.3 개인 맞춤 코스 생성

체력 처방값과 사용자 선호를 결합하여 최적 러닝 코스를 생성한다.

**두 가지 코스 생성 모드**:

| 모드 | 설명 |
|------|------|
| **핀 모드** | 지도에 경유지를 직접 찍어 코스 설계. 시작점 복귀 옵션 제공 |
| **거리 모드** | 원하는 거리와 출발점을 지정하면 자동 코스 생성 (편도/왕복 선택) |

**경로 성격 다축 평가**:
- **경사도 축**: 완만(flat) / 보통(gentle) / 가파른(hilly) — 구간별 경사율 기반 점수화
- **길 성격 축**: 신호등 적은 길(trail) / 흙길·트레일(soft) — 다중 선택 가능, 축별 독립 점수
- 가중치: 경사 스타일 0.7, 거리 0.3, 길 성격 각 0.7

**기술 스택**:
- 실제 보행 경로 라우팅: OSRM (무료, 키 불필요) / ORS (정밀, API 키 선택)
- 실제 고도 조회: Open-Meteo DEM API
- 경사 계산: 구간별 경사율 → 5단계 색상 표시 (급내리막~급오르막)

> **[스크린샷 C: 코스 생성 화면 — 경로 비교 카드]**

### 3.4 큐레이션 코스 추천

서울 14개 인기 러닝 코스를 큐레이션하여 제공한다.

각 코스에 대해 실제 보행 경로로 스냅하여 정확한 지도와 고도 프로파일을 보여주며, 안전 정보(가로등 밝기, CCTV, 야간 적합도), 편의시설, 경관 태그를 포함한다.

> **[스크린샷 D: 추천 코스 상세 화면]**

### 3.5 GPS 기록 + 음성 내비게이션

생성된 코스를 따라 실제로 달리는 기능을 제공한다.

**GPS 기록**:
- 실시간 위치 추적, 거리·페이스·시간 표시
- 긴 공백 뒤 유령 거리 방지 (GPS 점프 필터링)
- Wake Lock으로 화면 꺼짐 방지

**음성 내비게이션** (Web Speech API, 무료):
- 턴 감지: 방위각 변화 30° 이상, 최소 구간 15m, 포인트 간격 8m
- 5종 방향: 좌회전, 우회전, 급좌회전, 급우회전, 유턴 (150° 이상)
- 왕복 코스 반환점 안내: "왔던 길로 되돌아갑니다"
- km 단위 진행 안내, 도착 안내

**내보내기**:
- GPX 파일 내보내기
- Strava 연동 (OAuth + 자동 업로드)

> **[스크린샷 E: GPS 기록 화면 — 음성 내비게이션 실행 중]**

### 3.6 공공체육시설 안내

코스 경로를 따라 500m 이내의 공공체육시설을 자동으로 검색하여 표시한다.

- 데이터셋 15107764의 시설 좌표와 편의정보 활용
- 출발점/도착점 확대 검색 (러너 이용 가능성 높은 구간)
- 화장실, 주차장, 샤워실, 보관함, 트랙 유무 표시
- 코스 생성, 추천 코스, 경로 상세 3개 화면에 통합

> **[스크린샷 F: 근처 공공체육시설 안내]**

### 3.7 혼잡도 추정

서울 주요 지역의 시간대별 혼잡도를 추정하여 쾌적한 러닝 시간을 추천한다.

**모델 구성**:
- **15개 핫존**: 강남역(0.95), 홍대입구(0.90), 광화문(0.85) 등 상업 밀집 지역
- **11개 콰이어트존**: 한강공원(0.25), 서울숲(0.30), 올림픽공원(0.20) 등 공원·하천
- **24시간 시간대별 보정**: 출퇴근 피크(0.90~0.95), 새벽(0.08)
- **주말 보정**: 평일 대비 0.7배

**4단계 레벨**: 여유(low) / 보통(moderate) / 혼잡(high) / 매우 혼잡(very-high)

경로를 따라 최대 15개 지점을 샘플링하여 평균 혼잡도를 산출하고, 해당 경로에서 **가장 한적한 시간대 3개**를 추천한다.

> **[스크린샷 G: 혼잡도 배지 + 시간 추천]**

### 3.8 국민체력100 참여 현황

### 4.3 주요 알고리즘

**1) 분위 기반 연속 보간 처방**

```
입력: 사용자 VO₂max = 38.5, 남성, 30대
                   ↓
코호트 선택: male_30 분위 테이블
                   ↓
백분위 산출: percentile(38.5, male_30_vo2max) = 62
                   ↓
앵커 보간: anchor[50]=4.0km, anchor[75]=5.5km
           → interpolate(62) = 4.96km
                   ↓
처방: 거리 4.96km, 최대 경사 6.2%, 인터벌 15%
```

기존 러닝 앱의 "초급/중급/고급" 3단계 분류와 달리, **101개 분위에서 연속 보간**하므로 인접 백분위 사용자 간 처방 차이가 0.2km 이내로 매끄럽게 이어진다.

**2) 다축 독립 점수화**

경로 후보를 여러 개 생성한 뒤, 각 축(경사·거리·길 성격)별로 **독립적으로 점수를 산출**하고 가중 합산한다. 기존 가중치 방식처럼 한 축의 극단값이 다른 축 점수를 삼키는 현상을 방지한다.

```
총점 = style_score × 0.7 + distance_score × 0.3
       + trail_score × 0.7 (선택 시)
       + soft_score × 0.7 (선택 시)
```

**3) 경로 기반 시설 검색**

단순 반경 검색이 아니라, **경로를 20등분하여 각 지점에서 검색**하고 출발/도착점은 1.5배 확대 반경을 적용한다. 이를 통해 "코스를 따라 가다가 만나는 시설"을 정확히 찾아준다.

**4) 혼잡도 추정 모델**

핫존과 콰이어트존의 영향을 Haversine 거리 기반 역비례로 합산한다:

```
baseDensity = max(hotZone_influence) × min(quietZone_dampening)
congestion  = baseDensity × timeMultiplier[hour] × weekendScale
```

## 9. 결론

**런코스**는 국민체력100 공공데이터를 **개인에게 환원**하는 서비스이다.

295만 건의 체력측정 데이터에서 연령·성별 체력 분포를 추출하고, 사용자의 체력을 이 분포 위에 놓아 101개 분위 기반의 **연속적인 코스 처방**을 제공한다. 여기에 공공체육시설 좌표 데이터를 결합하여 경로 주변 편의시설을 안내하고, 측정건수 데이터를 시각화하여 제도의 가치를 전달한다.

단순한 데이터 조회·시각화를 넘어, 공공데이터가 **러너의 발걸음을 직접 안내하는** 실용적 서비스로 구현되었다.

설치 없이 웹 브라우저에서 즉시 사용할 수 있는 PWA로 제공되며, GPS 기록, 음성 내비게이션, GPX 내보내기, Strava 연동 등 실제 러닝에 필요한 기능을 완비하였다. 1,749개의 자동화 테스트로 데이터 무결성과 기능 안정성을 지속적으로 검증한다.
