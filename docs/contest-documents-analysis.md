## 3. 중요 발견사항

### 3.1 보고서 분량 초과 (CRITICAL)

**공고: 10장 이내** vs **현재: ~20장 이상**

현재 `contest-report.md`는 608줄로, PDF 변환 시 약 20~25페이지가 될 것. **절반 이상 축약 필요.**

축약 전략:
- §4 기술 아키텍처: 다이어그램 1개 + 표 1개로 축약
- §6 검증 체계: 표 1개로 압축 (검증이 있다는 사실만)
- §7 발전 방향: 표 1개로 통합
- §8 제한사항: 삭제 또는 1줄로 축약
- §9 심사기준 대응: 삭제 (보고서 자체가 심사기준에 답해야지, 심사기준을 나열하면 안 됨)
- 코드 블록/ASCII 다이어그램: 이미지로 대체

### 3.2 구축 완료일 미기재

보고서에 **"서비스 구축(승인) 완료일"**이 없음. 반드시 2026.6.8 ~ 10.2 사이의 날짜를 기재해야 함.
- GitHub 커밋 히스토리가 증빙이 될 수 있음
- 배포 URL의 최종 업데이트 날짜 활용

### 3.3 증빙자료 별도 제출

보고서와 별개로 **증빙자료**를 따로 제출해야 함:
1. 서비스 구축 완료일 증빙 (GitHub 배포 기록, 커밋 로그 등)
2. 운영주체 증빙
3. 서비스 URL 접속 화면 캡처
4. 기대효과 정량·정성 자료
5. KSPO 데이터 활용 부분 증빙 (코드 스니펫, 데이터 흐름도)

### 3.4 접수방법 확인

- **온라인 링크**로 제출: https://www.gov-eformsign.com/?s=4rViOw
- 이메일이 아님. gov-eformsign 사이트에서 서류 업로드
- 접수 마감까지 **수정 제출 가능** (같은 과제명으로)

### 3.5 시상식 발표 준비

- **발표심사 없이 서류심사만** 진행
- 단, 시상 시 **수상작 PT(5분 내외)** 필수
- → 수상 시를 대비한 PT 준비 필요

### 3.6 발전가능성 = 특별상 기준

공고문에서 특별상은:
> 대상·우수상을 제외한 팀 중, 종합점수 10위 이내이면서 **"발전가능성" 점수가 상위 2개**인 팀

우리 보고서의 발전가능성 섹션에서 **사업화·매출발생 가능성**을 더 구체적으로 어필해야 함.

### 3.7 국내외 시장·경쟁 현황 누락

필수항목 2번 세부사항 중 **"국내외 시장 및 경쟁 현황"**이 보고서에 별도 섹션으로 없음.
- Strava, Nike Run Club, 런데이 등과의 비교는 §9.1에 간략히 있지만
- 국내 러닝 앱 시장 규모, 러닝 인구 통계 등 **시장 데이터** 추가 필요

### 3.8 스크린샷 미삽입

보고서에 `[스크린샷 A~H]` 플레이스홀더만 있고 실제 이미지 없음.
- **구현 이미지 필수** (공고문 세부항목)
- 10장 분량 제한 고려하면 6~8장이 적정

## 4. 우리의 강점 (공고문 기준)

### 절대적 강점
1. **실제 운영 서비스**: PWA 배포 완료, URL 접속 가능 → "아이디어 기획/제안 과제 불가" 요건 충족
2. **KSPO 데이터 3건 활용**: 1건 이상 필수인데 3건 활용
3. **데이터 활용 깊이**: 단순 조회가 아닌 통계 분석 → 모델 입력 수준
4. **기술적 완성도**: 1,749개 테스트, 다영역 구현
5. **소스코드 공개**: GitHub 투명성

### 상대적 강점 (다른 출품작 대비 예상)
1. 대부분의 출품작은 데이터 시각화 or 단순 조회 앱 → 우리는 데이터가 서비스 로직의 핵심
2. Cooper 12분 검사 + VO₂max 연동은 학술적 깊이
3. 혼잡도 모델은 데이터 융합(KSPO + 환경 데이터) 사례

1. **APK 제출 불가**: "출처를 알 수 없는 APK파일 제출 불가" → PWA이므로 해당 없음
2. **타 대회 수상작 제외**: 이 작품이 다른 대회에서 입상한 적 없어야 함
3. **수정 제출 가능**: 마감 전까지 같은 과제명으로 재제출 OK
4. **다작 응모 가능**: 여러 작품 출품 가능하나 수상은 1개만
5. **저작권**: 수상작은 공단 이용 동의 필요 (자료집, 온라인 게재)
6. **상금 세금**: 기타소득 22% 공제 후 지급
