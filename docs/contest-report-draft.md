## 2-2. 서비스 전체 개요

런코스는 **국민체력100 측정결과에서 뽑아낸 연령·성별 체력 분포 위에 사용자를 올려놓고, 그 위치에 맞는 러닝 코스를 처방하는** 서비스다.

사용자가 나이·성별과 체력 측정값(또는 앱 내 12분 검사 결과)을 넣으면, 같은 또래 분포에서 **백분위**를 산출하고 그에 비례하는 **거리·경사·인터벌 비율**을 계산한다. 이 처방값으로 실제 보행 경로를 생성해 지도에 그리고, 경로 주변의 **공공체육시설**과 시간대별 **예상 혼잡도**를 함께 안내한다. 코스를 정하면 GPS로 기록하며 음성으로 길을 안내한다.

```
체력 입력 ──▶ 백분위 산출 ──▶ 거리·경사 처방 ──▶ 코스 생성 ──▶ 기록·음성 안내
 (또는 12분 검사)   (국민체력100)    (연속 보간)      (실제 보행로)    (GPX·Strava)
                                                        │
                              공공체육시설 안내 ◀────────┤
                              예상 혼잡도·추천 시간대 ◀──┘
```

## 2-3. 서비스의 우수성 및 필요성

**문제.** 러닝은 진입장벽이 가장 낮은 운동이지만, **자기 체력에 맞는 코스를 고르는 일**은 여전히 어렵다.

| 문제 | 현상 | 원인 |
|------|------|------|
| 체력 수준을 모른다 | 러너 대부분이 자기 체력의 객관적 위치를 모른다 | 체력 측정 데이터가 집계 통계로만 존재하고 개인에게 돌아오지 않는다 |
| 코스 미스매치 | 초보자는 급경사에서 포기하고, 상급자는 평지에서 지루해한다 | 코스 추천이 '거리' 한 축에만 의존한다 |
| 정보 분절 | 경로·시설·혼잡도가 서로 다른 서비스에 흩어져 있다 | 공공데이터가 하나의 서비스로 묶이지 않았다 |

**해결.** 국민체력100은 2010년 이후 **누적 273만 건**의 측정을 쌓아 왔지만, 이 데이터는 개인에게 "당신은 또래 중 몇 번째"라는 형태로 돌아오지 않는다. 런코스는 그 분포를 서비스 안으로 들여와, **집계 통계를 개인 처방으로 환원**한다.

**우수성.** 기존 러닝 앱(Strava·Nike Run Club·런데이 등)은 **기록 중심**이다. GPS로 달린 결과를 저장하고 통계를 보여주며, 코스 추천은 인기순이나 거리 필터에 의존한다. 런코스는 **처방 중심**이다. 달리기 전에 "당신 체력이면 이 거리, 이 경사"를 먼저 제시하고 그에 맞는 코스를 만들어 준다. 공공 체력 데이터가 서비스의 부가 정보가 아니라 **작동 원리 그 자체**인 구조다.

## 2-4. 국내외 시장 및 경쟁 현황

**시장.** 국내 러닝 인구는 팬데믹 이후 급증해 러닝 크루·마라톤 대회 참가가 크게 늘었다. 국민체력100 측정건수 자체가 이 흐름을 보여준다 — 2020년 코로나로 8.1만 건까지 떨어졌다가 **2025년 28.1만 건**으로 회복했고, 인증센터는 **89곳**으로 늘었다.

**경쟁 현황.**

| 구분 | 대표 서비스 | 강점 | 공백 |
|------|-----------|------|------|
| 글로벌 기록형 | Strava, Nike Run Club | 기록·소셜·세그먼트 | 체력 진단 없음. 코스 추천은 인기순 |
| 국내 코칭형 | 런데이 | 초보자 단계별 프로그램 | 고정 커리큘럼. 개인 체력 측정 반영 없음 |
| 지도·코스형 | 각종 코스 지도 서비스 | 코스 목록 제공 | 체력과 코스가 연결되지 않음 |
| **런코스** | — | **체력 백분위 → 코스 처방**, 시설·혼잡도 결합 | 현재 서울 한정 |

경쟁 서비스들이 공통으로 비운 자리는 **"내 체력에 맞는 코스"** 다. 이 질문에 답하려면 개인 체력을 모집단과 견줄 기준선이 필요하고, 그 기준선을 공개된 형태로 가진 곳이 국민체력100이다. 런코스의 차별점은 이 데이터를 실제 처방 로직에 넣었다는 데 있다.

# 3) 서비스 내용 상세

## 3-1. 체력 평가 — 국민체력100 분포 위에 나를 놓기

나이·성별·측정값을 넣으면 같은 또래 분포에서 백분위가 나온다. 12개 코호트(남녀 × 20~70대 이상)마다 101개 분위 테이블을 갖고 있어, 값 사이는 선형 보간한다.

- 측정값이 있으면 그대로 쓰고, 없으면 **앱 내 12분 검사**로 만든다
- 심폐지구력 자료가 부족한 또래(70대 이상 등)에는 처방을 억지로 내지 않고 **그 사실을 그대로 알린다**

> **[스크린샷 A: 체력 평가 입력 + 백분위 결과 화면]**

## 3-2. Cooper 12분 검사 (앱 내장)

별도 장비 없이 앱에서 12분 달리기 검사를 수행해 최대산소섭취량을 추정한다.

- GPS 첫 수신 시점에 벽시계 기준으로 타이머 시작, 검사 프로토콜상 **일시정지 불가**
- 남은 시간 음성 안내 (10분·5분·3분·1분·10초)
- 종료 시 추정값·또래 백분위 표시, GPS 정확도가 나쁘면 **오차 경고를 함께 표시**

> **[스크린샷 B: 12분 검사 실행 화면]**

## 3-3. 개인 맞춤 코스 생성

처방값(거리·경사)과 사용자 취향을 함께 넣어 실제 보행 경로를 만든다.

| 모드 | 방식 |
|------|------|
| 핀 모드 | 지도에 경유지를 찍어 설계. 시작점 복귀 선택 가능 |
| 거리 모드 | 원하는 거리와 출발점만 주면 자동 생성 (편도/왕복) |

경로 성격은 **경사도 축**(완만/보통/가파른)과 **길 성격 축**(신호등 적은 길, 흙길·숲길)을 **각각 독립으로 점수화**한다. 한 축의 극단값이 다른 축 점수를 삼키지 않도록 한 설계다. 후보 경로를 여러 개 만들어 비교 카드로 보여주고, 왜 이 코스인지 문장으로 설명한다.

실제 도로·보도를 따르며(OSRM/ORS), 고도는 DEM에서 조회해 구간별 경사를 5단계 색으로 그린다.

> **[스크린샷 C: 코스 생성 — 지도 + 경로 비교 카드]**

## 3-4. 공공체육시설 안내 (데이터셋 15107764)

만든 코스나 추천 코스를 열면 **경로 주변 500m 이내 공공체육시설**을 자동으로 찾아 보여준다. 단순 반경 검색이 아니라 경로를 20등분해 각 지점에서 찾고, **출발·도착점은 반경을 1.5배로 넓힌다** — 러너가 실제로 들를 확률이 높은 지점이기 때문이다.

서울 **1,284개소**를 25개 자치구 전역에서 검색한다.

> **[스크린샷 D: 근처 공공체육시설]**

## 3-5. 예상 혼잡도와 추천 시간대

경로 위 지점들을 샘플링해 시간대별 예상 혼잡도를 계산하고, **가장 한적한 시간대 3개**를 추천한다. 서울 상업 밀집지 15곳과 공원·하천 11곳의 위치, 24시간 시간대 계수, 주말 보정을 결합한 자체 추정 모델이다.

> 이 모델은 통계 기반 **추정**이며 실시간 계측이 아니다. 화면에도 '예상 혼잡도'로 표기한다.

> **[스크린샷 E: 예상 혼잡도 + 추천 시간대]**

## 3-6. 기록과 음성 안내

- **GPS 기록**: 거리·페이스·시간 실시간 표시. 신호가 끊겼다 돌아올 때 생기는 유령 거리를 걸러낸다. 화면 꺼짐 방지(Wake Lock)
- **음성 내비게이션**: 브라우저 내장 음성 합성으로 턴바이턴 안내(좌·우·급좌·급우·유턴). 왕복 코스 반환점 안내. **추가 비용 없음**
- **내보내기**: GPX 파일 저장, Strava 연동 업로드

> **[스크린샷 F: 러닝 기록 화면 — 음성 안내 중]**

## 3-7. 국민체력100 참여 현황 (데이터셋 15114286)

추천 코스 화면 하단에서 제도의 규모를 보여준다 — 누적 측정건수, 연도별 추세, 서울 인증센터 현황. **측정을 받으면 더 정확한 처방을 받을 수 있다**는 동기를 만드는 자리다.

## 4-2. 15108938 — 체력측정결과 (핵심 활용)

**수집.** 엔드포인트 `SRVC_NFA_TEST_RESULT/TODZ_NFA_TEST_RESULT_NEW`에서 12개 코호트 × 약 4,000건, **총 47,976건**을 수집했다. 페이지를 순서대로 받으면 특정 시기에 쏠려, **연도별로 균등하게 나눠 받는 방식**으로 바꿨다.

**정제 — 원본 데이터의 한계를 찾아 해결한 부분.** 이 데이터셋은 API 명세만 보고는 알 수 없는 함정이 두 개 있었다.

| 발견 | 문제 | 해결 | 검증 |
|------|------|------|------|
| **심폐지구력 측정방식이 섞여 있다** | 왕복오래달리기(f030)와 스텝(f037)·트레드밀(f035)의 값 눈금이 다르다 | 왕복오래달리기 제외, 스텝·트레드밀만 사용 | 6개 코호트 전부에서 왕복 방식 중앙값이 **2~3 낮음**을 교차 확인 |
| **악력 좌·우 중 무엇을 쓰는지 명세에 없다** | 좌·우가 따로 오는데 기준이 불명확 | max(좌, 우) 채택 | 명세의 상대악력(f028)을 역산하니 `max(좌,우)÷체중×100`이 **1,000행 전부 일치** |
| 미측정값이 0으로 온다 | 0이 '측정 안 함'인지 '실제 0'인지 구분 불가 | 0값을 미측정으로 분리 | 0값 72,015건과 실제 이상치 154건을 분리 |
| BMI 신뢰성 | 계산값인지 확인 필요 | 체중÷신장² 역산 대조 | 3,000건 중 2,999건 일치 (1건은 반올림 차이) |

**활용.** 코호트당 4,000건을 **101개 분위로 압축**해 앱에 싣는다. 사용자 값이 들어오면 이 분위 테이블에서 백분위를 보간하고, 백분위에 앵커를 걸어 거리·경사·인터벌을 **연속으로** 처방한다.

```
VO₂max 38.5, 남성 30대
   ↓  male_30 분위 테이블에서 백분위 = 62
   ↓  앵커 보간: 50분위 4.0km, 75분위 5.5km → 62분위 ≈ 4.96km
처방: 4.96km, 최대 경사 6.2%, 인터벌 15%
```

기존 앱들의 "초급/중급/고급" 3단계 분류와 달리, **인접 백분위 사이 처방 차이가 0.2km를 넘지 않는다**(자동 검증 항목). 51분위와 52분위 사용자가 전혀 다른 코스를 받는 절벽이 생기지 않는다.

## 4-3. 15107764 — 공공체육시설

`SRVC_SFMS_FACIL_INFO/TODZ_SFMS_FACIL_INFO`에서 전국 데이터를 받아 **서울 1,284개소**를 추렸다(폐업·삭제·좌표 없는 행 제외). 자치구가 비어 오는 행은 도로명 주소에서 자치구를 파싱해 채웠고, **주소마저 없으면 비워 둔다**.

> **정직성 원칙.** 초기 구현에서는 시설명 키워드로 편의시설(화장실·샤워실 등)을 추측해 표시했으나, **개방 데이터에 없는 정보를 지어낸 것**이라 판단해 전부 제거했다. 현재 화면에 나오는 값은 모두 개방 데이터에 실제로 실린 필드다.

## 4-4. 15114286 — 측정건수

`SRVC_TODZ_NFA_TEST_CENTER_CNT`에서 **8,161행 전량**을 받아 집계했다.

| 지표 | 값 |
|------|-----|
| 누적 측정건수 (2010~) | **2,738,202건** |
| 연도별 추세 | 2010~2025년, **16개년** |
| 2025년 측정 / 인증센터 | 280,667건 / **89곳** |
| 서울 인증센터 | **22곳**, 누적 405,822건 |

집계 과정에서 실제 응답 스키마가 `center_nm / test_ym / test_cnt` 구조임을 확인하고 매핑을 바로잡았다. **연령대별 참여 비율은 이 데이터셋에 없는 지표**여서 화면에서 제거하고, 대신 실제로 있는 서울 인증센터 현황을 넣었다.

## 5-2. 정성적 효과

**1. 데이터의 개인 환원.** 국민체력100 데이터가 집계 통계로만 존재하던 상태에서, 개인에게 *"당신은 또래 중 62번째"* 라는 구체적 피드백으로 돌아온다. 공공데이터의 가치가 실제 사용자 경험으로 전달된다.

**2. 제도 참여 유도.** 정확한 처방을 받으려면 실제 측정값이 필요하다는 구조 자체가 국민체력100 측정 참여 동기가 된다. 서울 22개 인증센터 현황을 함께 보여줘 **어디서 측정받을 수 있는지**까지 연결한다.

**3. 데이터 결합의 가치.** 체력(어떤 코스가 맞는가) + 시설(어디서 출발하면 편한가) + 혼잡도(언제 달리면 쾌적한가)를 묶어, 단일 데이터셋으로는 불가능한 답을 만든다.

**4. 공공체육시설 이용 촉진.** 코스 주변 시설을 자동으로 안내해, 러너가 몰랐던 인근 시설의 존재를 알린다.

## 6-4. 기술적 난제와 해결

1. **측정방식 혼재 발견** — 명세에 없던 심폐지구력 척도 차이를 데이터 분석으로 찾아내 6개 코호트 교차검증 후 분리
2. **악력 기준 역산 증명** — 상대악력 필드를 역산해 공단이 쓰는 값이 max(좌,우)임을 1,000행에서 확인
3. **iOS 음성 제한 우회** — 사용자 제스처 없이 음성 합성이 막히는 문제를, 제스처 시점에 빈 발화로 미리 열어 해결
4. **유령 거리 제거** — GPS 신호가 끊겼다 돌아올 때 직선 거리가 더해지는 문제를 시간·속도 기반으로 필터링
5. **초기 로딩 분리** — 시설 데이터 420KB가 홈 화면 번들에 얹히던 것을 지연 로딩으로 분리 (메인 번들 495KB → 288KB)

# 10) 결론

런코스는 국민체력100 데이터를 **개인에게 돌려주는** 서비스다.

47,976건의 측정 표본에서 연령·성별 체력 분포를 뽑아 12개 코호트 × 101개 분위 테이블로 만들고, 사용자를 그 분포 위에 올려 **연속적인 코스 처방**을 낸다. 여기에 서울 1,284개 공공체육시설 좌표를 결합해 경로 주변 시설을 안내하고, 273만 건의 측정건수 집계로 제도의 규모를 전한다.

데이터를 조회해 보여주는 데서 그치지 않고, **공공데이터가 러너의 발걸음을 실제로 안내하는** 서비스로 구현했다. 설치 없이 브라우저에서 바로 쓸 수 있으며, GPS 기록·음성 내비게이션·GPX 내보내기까지 러닝에 필요한 과정을 갖췄다. 13,267개의 자동 검증이 데이터 무결성과 기능 안정성을 지속적으로 지킨다.

무엇보다, **개방 데이터에 없는 값은 만들어 넣지 않았다.** 편의시설 추측 표시와 연령대 비율을 스스로 걷어낸 것은, 공공데이터를 다루는 서비스가 지켜야 할 최소한이라고 판단했기 때문이다.
